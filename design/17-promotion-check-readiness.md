## The tool

- **REST calls (all reads):** the provider's id (`GET /configuration`); the provider's own list of spaces (`GET /spaces`); the dataset's id (`POST /lookup-file-id/{path}`), or, for a space whose name another space shares, the space's own directory (`dirId` from the list, else `GET /spaces/{id}`); a recursive listing of the dataset (`GET /data/{id}/files`, 1000 per page); each file's block map (`GET /data/{id}/distribution`); Onezone's `online` for a provider holding blocks (`GET /providers/{id}`); the space's ongoing transfers (`GET /spaces/{id}/transfers`, then `GET /transfers/{id}`, at most 50); a placement rule this process made (`GET /qos_requirements/{id}`). Every id in a path is one encoded segment (`id_segment`).
- **Input:** `extent`, 1–20 items, each `{dataset, files?, date_ranges?}`.
- **Read-only:** `readOnlyHint: true`; not in `token_policy.WRITE_TOOL_NAMES` (a test pins both).
- **Code:** `onedata_mcp/modules/readiness.py` (surface) and `onedata_mcp/api/readiness.py` (logic, errors). The rule that selects an item's files is one pure function, `select_paths`, which the scorer also uses.

### How a trial is judged

- **Answer readers.** RC, RCn, RCp and RCi share V4's and V5's vocabulary (`rubrics._CHECK`), reordered so that no passing label is first: NOT_READY_OTHER, SAYS_READY, NOT_READY_ELSEWHERE, NOT_READY_WRITING, OTHER. SAYS_READY means all the files asked about are ready. The deterministic reader reads a ready claim per clause: a remark about other files after "while" or "but" does not undo it, nor does another site named only as the source ("copied from <owner>"); a clause that names another site otherwise is no ready claim ("complete at <owner>, with nothing at <local>"); it is undone when the answer also says files are still being written, gives a verdict of not ready, or claims ready of some files only ("three of the files"; "all five of the files" is all). Both readers return, beside the label, the names AND counts the answer gives for the files being written (`#2`, `#all`), read before or after the phrase ("still being written: 4 files", "for all 5 files", "both"; after it, only behind a colon, a parenthesis or a preposition, never across a comma), never from a time, size or number of tries ("after 150 s"), with clauses split on a colon, a dash, "because", "since", ", as", and an "and" that joins two clauses (not a list of names); a writing clause that names no file takes the names of the subject before such a split ("- log_20200101.dat: still being written", "… because it is still being written"). A name is an example (one true name passes), a count a claim about the whole ("all five are being written" fails), `oracles.writing_claim_problems`. A claim that the other files are not here is read too (`others:not_ready`) and checked against the state at the answer (false in RCn), and so is a claim that they are ready here (`others:ready`: false in V5, where they are at the owner only; the verification round). Also since that round: a partitive whole ("of the five files, some …"), a try ("on attempt 4", "poll #3") or an ordinal is no count; an "and" between coordinated file names does not split them; a clause saying ready, readable, local or here ends a list of names being written; and a ready claim at this site stands beside a replica named elsewhere ("ready at <local> and at <owner> as well"), not beside a copy on its way. Since the second verification round: a ready claim is bound to the places stated for it (any order: "ready at <owner> and at <local> as well" is ready here; "complete at <owner> and being transferred here" is not; "the other three are ready only at <owner>" is no `others:ready`); a try given as a word is no count; "a total of four" counts (only "of the N" and "out of N" name a larger group); two file names sharing one verb stay together. RCo is read by V1's reader. A disagreement with the judge is NEEDS_REVIEW; the rubric was aligned with the reader, which changes its hash, so verdicts stored before are not reused.
- **Required call** (RC, RCn, RCp, RCi): successful `check_readiness` calls that, between them, established the state of every file asked about, read per file (by its id, in the trial's space) from each call's own record (`CallRecord.audit["resolved"]`: the files the tool resolved, their final state and the extent items that selected each; a file left unchecked does not count). Every readiness call has a record, empty when it resolved nothing (a configuration timeout); a call with none is a trace from before the record, never read from its arguments: the trial is a harness outcome (the verification round). RCp: only calls whose every selected file, checked or not, in any space, is one of the three count. RCi: only files that an item giving the dataset by the space's id selected. RCo requires nothing.
- **Restraint:** any write that may have taken effect fails the trial (a schedule, a rule); local blocks and rules are compared with the start at the answer and after the window.
- The shared checks of design/08's "Scoring" apply.
