## Headline numbers (3 layers of view)

The benchmark measures **MCP-server effectiveness**: did the model
+ MCP tool surface complete the federated-data task. Trial-failures
decompose into three classes that the paper should distinguish:

| Class | Definition | What it measures |
|---|---|---|
| **MCP / model failure** | Model failed to navigate the MCP surface or reason correctly | Real benchmark signal; paper data |
| **Oracle parser bug** | Model was right; the test harness mis-parsed the answer | Test-harness bug; not science |
| **Deployment artefact** | Model attempted the right MCP call; serving layer (vLLM) dropped it | vLLM tool-call-parser issue; not MCP server |

The cleaned data layers (each preserves originals, adds sidecars):

|---|---|---|---|

## Data-cleaning methodology (Threats to Validity)

### Audit trail

Original sweep artefacts preserved in two locations:
- **In-place sidecars**: each `<llm>__<scenario>.jsonl` is
  unmodified; cleaned data lives in `<llm>__<scenario>.rescored.jsonl`
  with both `_original` and `_v2` fields per trial.
- **Hard backup**: `artefacts/20260503T002305_k8_BACKUP_<timestamp>/`
  (full byte-for-byte copy at backup time).

### Lift policy (lift-only, never demote)

Rescore can flip FAIL → PASS but never PASS → FAIL.

**Rationale:** the original oracle ran AT TRIAL TIME against the
real federation. Its PASS verdict is more authoritative than an
offline replay against stubbed federation responses. Conversely, if
the rescore says PASS, the new parser logic found something the old
parser missed — that's a genuine lift.

### Layer 1 — parser-bug lift (20 trials)

Three parser bugs identified mid-K=8-sweep, fixed in
`benchmark/oracles/_helpers.py` post-sweep:

1. **Case-sensitivity**: `extract_int(text, "size")` couldn't match
   "Size: 57" (capital S). Affects D3 byte-counting.
2. **3-column markdown tables**: GLM emitted answers like
   `| name | <hex spaceId> | 3 |`. Pre-fix separator class wouldn't
   traverse alphanumeric chars between key and value. Affects D1.
3. **JSON-format answers**: Qwen D5 emitted
   `json: {"pipeline_stage": "raw", ...}`. Pre-fix `extract_kv_lines`
   only parsed kv-line format. Affects D5.

Each fix has a dedicated unit test using verbatim K=8 agent output as
the positive case (`test/unit/test_extract_helpers_replay.py`).

### Layer 2 — deployment-artefact lift (10 trials)

Trials where `final_answer` contains a literal serving-layer-leak
signature (e.g. `<tool_call>{...}</tool_call>` markup that vLLM's
`--tool-call-parser granite4` failed to route into the structured
`tool_calls` field). All 10 are Granite — **L-3** in
`research/llm-output-stability-findings.md`.

These are NOT MCP-server failures: the agent attempted the right
MCP call; the serving layer dropped it. For "MCP-server
effectiveness" they should count as PASS.

The paper's Threats to Validity section should explicitly note:
- Granite K=8 with vLLM `--tool-call-parser granite4`: 124/144 (86.1%)
- Without the lift: 114/144 (79.2%)
- The lift is justified by direct evidence in `final_answer`

### What we DIDN'T lift

- Stochastic flips on real reasoning gaps (e.g., GLM A5 malformed
  QoS expressions, Granite P1 geography knowledge gap, Devstral D1
  truncation on long lists). These are paper data points.
- Trials where the federation actually diverged (no instances at K=8).

The 52 remaining `model`-class failures are real model reasoning
gaps. They are the paper's substantive findings on capability gaps
across open-weight LLMs.

  Poland (EU) or `sk` = Slovakia (EU). Real reasoning gap, paper

  show variance.

  rows. Different shapes (Granite drops random rows; Devstral
  truncates).
